## Answer review

- **Sender readiness.** Both models answered the standalone sender question using the proposed shared status read. Qwen missed it in the matched named control. Keep this consolidation in the pilot.
- **Ads.** Qwen used the proposed report successfully for Google upload diagnostics. GPT-OSS chose collection booking readiness and missed the upload results. The current Meta fallback also produced confident statements about provider state from a saved PAUSED value. Surface the status source, observation time and unavailable fields explicitly in the report and its description.
- **Email.** Qwen read the saved audiences but tried unrelated audience filters and never persisted the two drafts. Those filter requests have no simulated reply. GPT-OSS exhausted the output budget. These runs establish neither real provider delivery nor an intrinsic inability to draft. A follow-up should test the intended draft path with sufficient output tokens, verify distinct IDs and bodies, and forbid invented coupon codes or booking URLs.
- **Access and modules.** Both models passed the proposed collection-boundary and inactive-advertising checks in this sample. The fixture enforces scope and intercepts writes. Production OAuth, role enforcement and commercial module activation require their own checks.
- **Grader calibration.** Review found that correct ISO dates using nonbreaking hyphens and qualified descriptions of unknown campaign state could be marked wrong. The table uses a corrected rubric replayed against the original answers and tool traces. Runtime failures retain their original scores. These are automated checks on selected facts and behavior. Read the transcripts for quality judgments.
